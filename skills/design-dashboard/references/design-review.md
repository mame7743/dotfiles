# 設計・点検ルール

以下は公式チェックリストの転載ではなく、本スキル独自の実務上の推奨。

## 表現の選択

| 利用者の問い | 第一候補 | 確認事項 |
| --- | --- | --- |
| 現在値・目標との差 | 数値と比較値 | 単位、期間、目標の根拠 |
| 項目の大小・順位 | 横棒・棒 | 並び順、長い項目名、原点 |
| 時間の変化 | 折れ線 | 時間間隔、欠測、比較期間 |
| 全体の内訳 | 積み上げ棒・100%積み上げ棒 | 実数か構成比か、合計と分母 |
| 2変数の関係 | 散布図 | 相関と因果の区別、重なり |
| 分布・ばらつき | ヒストグラム・箱ひげ | 区間、標本数、外れ値 |
| 正確な値・個別案件 | 表 | 単位、ソート、詳細への導線 |

円・ドーナツは少数カテゴリの大まかな構成把握に限定し、微差の比較には棒を優先する。グラフ不要なら数値や表を使う。
棒グラフは原則ゼロ基準とする。折れ線などで軸を切り詰める場合は範囲を明確にし、誇張の有無を確認する。比較チャートは単位と尺度を揃える。3D装飾や二重軸を安易に使わない。

## 統一性と余白

- 外側余白、カード内余白、要素間隔を既存トークンに合わせる。トークンがなければ小さな間隔体系を提案する。
- 同じ役割の見出し、数値、補足、凡例、ボタンを揃える。関連要素内の間隔はグループ間より小さくする。
- カードの端と見出しを揃える。内容の少ないカードを無理に引き伸ばさない。
- 色の意味を画面間で揃える。重要な例外に強調を集中させる。増加が良いか悪いかを業務定義から決める。
- 数値の桁数、日付、単位、百分率を揃え、日本語ラベルが切れない幅を確保する。
- 広い画面でも読みにくい行長や過剰な空白を避ける。狭い画面は主要情報の順序を維持して再配置する。

## データと操作

- 集計期間・母集団・フィルター・更新時刻が明確か。
- 全体値と絞り込み後の値が区別できるか。
- 欠損、ゼロ、未集計、取得失敗を区別できるか。
- ラベル・凡例・ツールチップに頼りすぎず、主要な結論を読み取れるか。
- 色以外の手掛かり、読みやすい文字・コントラスト、キーボード操作があるか。
- 個人や案件のデータは権限に応じて取得・表示されるか。非表示だけをアクセス制御としない。

## 利用シナリオで確認する

利用者の問いを1つ選び、対象期間を設定し、値を読み、比較し、必要なら明細へ進む。迷った箇所と誤解した箇所を具体的に記録して修正する。
CAE案件管理なら、遅延率は分母・判定日・納期変更の扱い、工数は予定/実績・単位、余力は稼働可能時間の定義を確認する。例示を業務要件として強制しない。
