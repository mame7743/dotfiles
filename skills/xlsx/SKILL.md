# XLSX の作成・編集・分析

| タスク | アプローチ |
|---|---|
| **作成**または**編集**（数式・書式付き） | `openpyxl` — 以下の注意点を参照 |
| **大量データ**の入出力 | `pandas`（`read_excel`、`to_excel`） |
| シートの**クイック確認** | `markitdown file.xlsx` — シートごとに `## SheetName` が出力されます。`.xlsm` も読み取れます。セル座標は表示されないため、これを基に編集を計画しないでください |
| モデルの**読み取り**（数式*と*値の両方） | `load_workbook` を2回実行 — 以下の注意点を参照 |

> `openpyxl`、`pandas`、`markitdown` はプリインストールされています。先に `pip install` を実行せず、スクリプトを書いて直接 import してください。import が失敗した場合（または `markitdown` コマンドがない場合）にのみ、不足しているパッケージを `pip install` してください。

> 以下のスクリプトのパスは、このスキルのディレクトリを基準とした相対パスです。

## すべての出力に必要な要件

- 全体を通して**プロフェッショナルなフォント**（Arial、Times New Roman）を使用してください。ユーザーが別途指示した場合はその限りではありません。
- **数式エラーはゼロにしてください。** `recalc.py` が `errors_found` を報告している間は、絶対に納品しないでください。エラーが自分の作業より前から存在していたと思われる場合は、そのことを証明してください。*元の*ファイルを `data_only=True` で読み込み、そのセルを確認してください。自分が導入したエラーは、既存のエラーとまったく同じように見えます。
- **ハードコードされた結果ではなく、数式を使用してください。** Python で計算した合計ではなく、`sheet['B10'] = '=SUM(B2:B9)'` と記述してください。入力が変わったときにシートが再計算される必要があります。
- **ユーザーの仕様を文字どおりに遵守してください。** タブ名、列ヘッダー、指定された数式も正確に守ってください。別の値を計算するような再設計は、どれほど洗練されていても失敗とみなされます。
- **すべての仮定とハードコードされた数値**を、読者が目にする場所（セルコメント、または表の末尾の隣接セル）に文書化してください。実在する情報源がある場合はそれを引用してください（`Source: Company 10-K, FY2024, Page 45, Revenue Note, [SEC EDGAR URL]`）。数値がユーザーから提供された場合は、その旨を明記してください。
- **誰かに記入してもらうために*あなたが作成する*ワークブック**には、どのセルを編集するかを示す短い凡例と、期待される形式を示す実際的な値のサンプル行を1行含めてください。編集を依頼されたファイルには、そのような行を絶対に追加しないでください。
- **既存ファイルを編集する場合: その規約に厳密に合わせてください。** 既存の規約がここでのすべてのガイドラインに優先します。まず指定された入力セル（異なるフォントカラー、塗りつぶし、または網掛けでマークされています）を特定し、そこにのみ書き込み、既存の数式はすべてそのまま残してください。

## 再計算（ファイルに数式が含まれる場合は必須）

openpyxl は数式を**キャッシュ値なしの**文字列として書き込みます。再計算を行うまで、
数式セルはキャッシュ値を読み取るもの（`pandas`、`load_workbook(data_only=True)`、ほとんどのプレビューア）に対してすべて `None` と読み戻されます。

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # default 30
```

LibreOffice がすべての数式を計算し、ファイルは**その場で書き換えられ**、JSON が返されます:
`status`（`success` | `errors_found`）、`total_formulas`、`total_errors`、およびエラーの種類ごとに最大100セルを列挙する `error_summary` です（`locations_truncated` は保留した件数を示します — リストの長さではなく `total_errors` を信頼してください）。指摘された箇所を修正し、再度実行してください。**`status` の代わりに `error` キーを持つ JSON は、何も再計算されていないことを意味し**、その場合のみ非ゼロで終了します — `errors_found` は0で終了するため、クリーンな終了をクリーンなワークブックとみなさないでください。

**緑色の再計算は、数式が*評価された*ことを証明するだけで、*正しい*ことを証明するものではありません。** オフバイワンの範囲や誤った行への参照は、クリーンでエラーなしのファイルを間違った数値とともに生成します。グリッド全体を作成する前に、まず2〜3個の数式を書いて、期待どおりの値を取得することを確認してください。

**別のファイルにリンクしているワークブックは**、openpyxl で再保存して再計算すると、そのリンクを失います。そのような数式は `='[1]Returns Analysis'!$B$2` と読み取られます — `[1]` はワークブックの外部参照リストへのインデックスであり、*ディスク上の別のファイル*を指し示すもので、シートを指すものではありません。そのファイルはここにはほとんど存在しないため、セルのキャッシュ値がそのデータを保持する唯一のものです。openpyxl は保存時にその値を削除し、LibreOffice は参照を実際に解決しようとして失敗し、`#NAME?` を書き込み、すべてのリンクを削除します。`recalc.py` はその状態での実行を拒否します — 上書き保存する前に、元のファイルからそれらのセルの値をコピーしてください（`--force` で上書きでき、損失を受け入れます）。

## 検証に耐える数式の選択

LibreOffice は Excel よりも少ない関数を実装しており、評価できない関数は納品するファイルに `#NAME?` として焼き付けられてしまいます。

- **Excel 2007 世代の関数を優先**してください — `SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT` — これらはプレフィックスを必要としません。
- **2007年以降の関数は6つだけ、`_xlfn.` プレフィックス付きで動作します**。openpyxl は数式を XML にそのまま書き込み、Excel は2007年以降の名前をプレフィックス付きで保存するためです（UI ではそのプレフィックスは隠されています）: `_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。プレフィックスなしで書くと、それぞれ `#NAME?` になります。
- **`XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE`、`SEQUENCE` は絶対に使用しないでください。** 実行環境の LibreOffice は*どの*プレフィックスでもこれらを評価できません。新しいビルドでは評価できますが、これらはスピルする配列関数であり、openpyxl で書き込まれたファイルにはスピルメタデータがないため、範囲の左上のセルのみに値が入り、`recalc.py` は切り詰められた結果に対して `total_errors: 0` を報告します。ルックアップには `INDEX`/`MATCH` を使用し、並べ替え・フィルタリング・重複除去はセルを書き込む前に Python 側で行ってください。
- LibreOffice が解析できなかった数式は**小文字にされて**書き戻されます — `#NAME?` の横にあるすぐわかる手がかりです。

## openpyxl の注意点

- **モデルの読み取りには2回のロードが必要です。** `data_only=True` ではキャッシュ値が得られ、数式は消えています。デフォルトでは数式文字列が得られ、値はありません。1回のパスで両方を得ることはできません。
- **`data_only=True` は保存すると破壊的です。** そのワークブックには数式が残っていないため、保存するとすべての数式がリテラル値に置き換えられ、恒久的になります。
- **openpyxl が書き込んだ直後のファイルに対する `data_only=True` は、どこでも `None` を返します** — まず `recalc.py` を実行してください。（結果が `""` の数式も `None` と読み戻されます。）
- **結合セル: 左上のアンカーのみに書き込んでください。** 範囲内の他のセルは `.value` が読み取り専用の `MergedCell` です。
- **`.xlsm` は、`load_workbook` に `keep_vba=True` を渡さないとマクロが失われます。**
- **空白を含むシート名は、シート間参照で引用符で囲む必要があります**: `='Assumptions Inputs'!$B$5`。引用符がないと `#VALUE!` と評価されます。

## 財務モデル

ユーザーが別途指示した場合、または既存ファイルがすでに別の方法を採用している場合は、この限りではありません。

**色:** ハードコードされた入力とシナリオレバーには青のテキスト（`0,0,255`）· 数式には黒 · 別のシートへのリンクには緑（`0,128,0`）· 別のファイルへのリンクには赤（`255,0,0`）· 主要な仮定とユーザーが記入すべきセルには黄色の塗りつぶし（`255,255,0`）。

**数値:** 通貨は `$#,##0` とし、単位をヘッダーに記載します（`Revenue ($mm)`）· ゼロは `-` と表示し、パーセンテージも同様です（`$#,##0;($#,##0);-`）· 負数は括弧で表示 · パーセンテージは `0.0%` で、**分数として保存**します（`0.15` は `15.0%` と表示され、`15` を保存すると `1500.0%` と表示されます）· バリュエーション倍率は `0.0x` · 年はテキストとして保存します（`"2024"`、決して `2,024` にしない）。

**構造:** すべての仮定をそれ専用のラベル付きセルに置き、それを使用する数式から参照します（`=B5*(1+$B$6)`、決して `=B5*1.05` ではない）· 行の途中で単一のセルが編集されるのが最も一般的な無言のエラーであるため、数式はすべての予測期間で一貫させる · ゼロになり得る分母にはガードを設けます。
